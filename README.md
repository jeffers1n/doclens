# DocLens

DocLens помогает искать ответы в своих документах. Загрузите инструкцию, несколько PDF или папку с документацией, задайте вопрос и откройте фрагмент, на который ссылается ответ.

Приложение работает в браузере на вашем компьютере. Для ответов можно выбрать локальную Qwen, Gemini или сравнить обе модели на одних и тех же источниках. Есть и обычный режим поиска, который показывает найденные выдержки.

## Что можно делать

- Загружать отдельные файлы и папки вместе с вложенными каталогами.
- Искать по словам и по смыслу. Например, вопрос о восстановлении данных может найти раздел про резервные копии, даже если формулировки отличаются.
- Получать ответы со ссылками на конкретные фрагменты. Для PDF указывается страница.
- Обновлять документы повторной загрузкой и удалять их из библиотеки.

Документы и поисковый индекс сохраняются между запусками. Аккаунт для локального режима не нужен.

## Запуск

Нужен Python 3.10 или новее со встроенным SQLite и поддержкой FTS5.

Склонируйте репозиторий или скачайте его через **Code → Download ZIP** на GitHub.

```sh
git clone https://github.com/jeffers1n/doclens.git
cd doclens
```

**macOS и Linux**

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

**Windows, PowerShell**

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Откройте [http://127.0.0.1:8030](http://127.0.0.1:8030). Терминал должен оставаться открытым, пока вы пользуетесь приложением. Для остановки нажмите **Ctrl+C**.

Уже на этом этапе можно загрузить файл и выбрать **Только поиск**. Без Ollama будет доступен поиск по словам. Настройка поиска по смыслу и локальных ответов описана ниже.

## Qwen и поиск по смыслу

Установите [Ollama](https://ollama.com/download). Для начала подойдут две модели.

```sh
ollama pull nomic-embed-text
ollama pull qwen2.5:1.5b
```

`nomic-embed-text` используется для поиска похожих по смыслу фрагментов. `qwen2.5:1.5b` составляет ответ по найденному тексту. Если модели уже есть в `ollama list`, скачивать их повторно не нужно.

Запустите приложение Ollama или команду ниже в отдельном терминале.

```sh
ollama serve
```

Обновите страницу DocLens, добавьте документы и выберите **Ответ Qwen · локально**. В режиме **Только поиск** embeddings тоже используются, а ответ модели не генерируется.

При загрузке папки дождитесь завершения индексации. Чем больше документов, тем дольше она займёт. Если Ollama недоступна, приложение сообщит о переходе к поиску по словам.

Можно использовать другую установленную текстовую Qwen. Перед запуском DocLens задайте точный тег из `ollama list` в переменной `QWEN_MODEL`.

```sh
# macOS / Linux, если эта модель уже установлена
QWEN_MODEL=qwen2.5:7b python server.py
```

```powershell
# Windows PowerShell
$env:QWEN_MODEL = 'qwen2.5:7b'
.\.venv\Scripts\python.exe server.py
```

Большие модели требуют больше памяти. По умолчанию выбран небольшой вариант 1.5B.

## Gemini

Для Gemini нужен свой ключ из [Google AI Studio](https://aistudio.google.com/apikey). Перед использованием проверьте тариф проекта и доступные квоты. В DocLens облачный режим включается для аккаунта на бесплатном тарифе без подключённого биллинга. Приложение проверяет ваше подтверждение в переменной окружения, а фактический тариф и лимиты задаёт Google. [Тарифы Gemini](https://ai.google.dev/gemini-api/docs/pricing).

Остановите DocLens через **Ctrl+C** и задайте ключ в том же терминале. Во время ввода ключ скрыт.

**macOS и Linux**, с активированным виртуальным окружением

```sh
export GEMINI_API_KEY="$(python -c 'import getpass; print(getpass.getpass("Gemini API key: "))')"
export GEMINI_FREE_TIER_CONFIRMED=yes
python server.py
```

**Windows PowerShell**

```powershell
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Gemini API key' -AsSecureString)).Password
$env:GEMINI_FREE_TIER_CONFIRMED = 'yes'
.\.venv\Scripts\python.exe server.py
```

Обновите страницу и выберите **Ответ Gemini · облако** или **Сравнить Qwen и Gemini**. Ключ читается из окружения серверного процесса. По умолчанию используется `gemini-3.5-flash-lite`. Другую доступную вашему проекту модель с поддержкой структурированного вывода можно указать в `GEMINI_MODEL`.

При выборе Gemini в Google отправляются вопрос, имена найденных файлов и до шести выдержек из них. Учитывайте это при работе с личными или рабочими документами.

## Первый вопрос

Для проверки можно создать текстовый файл с двумя предложениями.

> Резервные копии хранятся 17 дней. Для восстановления откройте раздел «Архив».

Загрузите файл и спросите «Сколько дней хранятся резервные копии?». Откройте ссылку `[S1]` рядом с ответом и сравните его с исходным текстом.

Повторная загрузка файла с тем же путём обновит его содержимое и индекс. Кнопка **×** рядом с именем удаляет документ из библиотеки приложения. Файл на вашем диске остаётся на месте.

## Поддерживаемые файлы

- PDF с текстовым слоем и DOCX, включая текст таблиц в основной части документа.
- Markdown, HTML, TXT, reStructuredText и AsciiDoc.
- Текстовые CSV, JSON, YAML и TOML в UTF-8.

Лимит одного файла — **12 МиБ** и **2 млн извлечённых символов**. Сканы требуют предварительного распознавания текста — OCR. Файлы с паролем, скрытые пути, неподдерживаемые форматы и служебные каталоги вроде `node_modules` пропускаются. После загрузки видны причины пропуска.

## Как устроен поиск

Текст делится на фрагменты до 1500 символов с перекрытием 140 символов, чтобы сохранить контекст на границах.

BM25 ищет совпадения слов с учётом их форм в русском и английском. Nomic преобразует документы и вопрос в embeddings — числовые представления текстов. Векторный поиск ранжирует фрагменты по косинусной близости. Оба списка объединяются методом Reciprocal Rank Fusion, после чего приложение показывает до шести источников и передаёт их выбранной модели ответа.

Векторы сохраняются в SQLite. После изменения файла старые векторы удаляются, после обновления весов модели индекс перестраивается. Для документов, добавленных без Ollama, embeddings создаются при следующем поиске. Прерванная индексация продолжается с ещё не обработанных фрагментов.

Основные файлы проекта:

| Файл | За что отвечает |
| --- | --- |
| `library.py` | Чтение документов, чанкинг, SQLite и объединение результатов поиска |
| `embeddings.py` | Локальные embeddings через Nomic |
| `models.py` | Ответы Qwen и Gemini |
| `server.py` | Локальный HTTP-сервер и API |
| `static/` | Интерфейс приложения |
| `tests/` | Проверки импорта, поиска и работы индекса |

## Данные и настройки

Текст, фрагменты и векторы хранятся локально в `data/library.sqlite3`. Исходные файлы и история ответов отдельно не копируются. Сервер слушает `127.0.0.1`.

| Переменная окружения | По умолчанию |
| --- | --- |
| `PORT` | `8030` |
| `DOCLENS_DATA_DIR` | Папка `data` внутри проекта |
| `QWEN_MODEL` | `qwen2.5:1.5b` |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` |
| `GEMINI_API_KEY` | Задаётся пользователем |
| `GEMINI_FREE_TIER_CONFIRMED` | Для Gemini требуется `yes` |

Папка `data/`, виртуальное окружение, файлы `.env` и ключи исключены через `.gitignore`.

## Что учитывать

Это pet-проект, и ответы стоит сверять с исходными фрагментами. Ссылка позволяет открыть фрагмент для проверки ответа. Небольшая Qwen может неверно понять вопрос или ответить по-английски, даже если инструкция задана на русском.

Nomic по умолчанию ориентирован на английский язык. Качество русскоязычного поиска и вопросов к документам на другом языке зависит от формулировки. Поиск по смыслу возвращает ближайшие фрагменты, даже когда в них нет нужного факта.

При ошибке Gemini найденные выдержки остаются доступны. Для HTTP 403 проверьте права ключа и доступность сервиса в вашем регионе, для HTTP 429 — квоты проекта.

## Тесты

Из папки проекта, используя Python виртуального окружения:

```sh
python -m unittest discover -s tests -v
```

Тесты работают с временными библиотеками. Облачные ответы в них имитируются.
